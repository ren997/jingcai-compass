## 市场改为亚盘（spreads+totals）+ 让球盘实测（2026-10-20）

- 用户要求：**只做让球盘 + 大小球，都是亚盘标准盘，不做胜平负**。
- **计费答复**：`markets=spreads,totals` 仍是 **2 credits/联赛**（计费=市场数×地区数，与市场类型无关），成本与 `h2h+totals` 完全相同。月成本仍为 450/500。
- **实测（`regions=eu`，英超 20 场，花 4 credits，余额 486→482）关键发现**：
  - `spreads` 确实含四分之一盘：-1.25/-0.75/-0.25/0.25/0.75/1.25 均出现 → 是真亚盘。
  - **18 家 bookmaker 只有 8 家报 `spreads`**，`totals` 有 18 家 → 让球盘数据薄。
  - **同一场比赛各家盘口最多相差一整球**（利物浦场：-1.0 / -0.5 / -0.25 / 0.0）→ **不能跨盘口取中位**，原算法（对 h2h 成立）对 spreads 无效。
  - 真亚盘线基本只有 Pinnacle + Matchbook 报（阿森纳 -1.25 @1.93/1.97）。
  - 存在离群价：利物浦场 coolbet 主 -1.0 @3.20 / 客 +1.0 @1.39。
  - `totals` 主盘集中：2.5 出现 442 次、3.0 仅 42 次。
- **新算法（已写入文档 7.1/7.2）**：主盘 = 使 `|p-0.5|` 最小的线（即亚盘"标准盘"本义）；按 line 分组取 p 中位 → 选最平衡线 → 只聚合该线（≥2 家）→ 剔除偏离中位 >0.08 的离群家 → 二选一市场另一边补 1-p。
  - **实测三次均命中 Pinnacle 的盘**（阿森纳 -1.25、维拉 0.75、利物浦 -0.25）；"众数"判据会选错（阿森纳场众数 -1.5 比真盘深 0.25）。
- **结算改为统一的 margin 模型**：`margin = (home-away)+line`（HOME）/ `(away-home)-line`（AWAY）/ `(home+away)-line`（OVER）/ `line-(home+away)`（UNDER），>0 赢、=0 走、<0 输；`.25/.75` 拆两半盘合并。验算：阿森纳 -1.25 胜 1:0 → margin=-0.25 → 拆 -0.5(输)+0(走) → HALF_LOSS ✅。
- **降级规则改写**：原"降级为 h2h"作废（h2h 已出范围），改为"降级为仅 `totals`"——因为 totals 报价家数多、主盘集中，spreads 更不可靠。
- 统计口径同步改：全赢率/含半赢率双口径，`PUSH` 不进分母；Brier 统一为二分类（原多分类作废）。
- 文档 `docs/v2-design.md` 升级到 **v0.3**，新增 3.1 让球盘实测、重写 7.1~7.4、更新 6.3/6.4 枚举、4.2 计费与降级、12 风险、13 决策记录。

## v1 亚盘链路断裂核实 + 亚盘模型设计（2026-10-20，仅新增 docs）

- **重要发现：v1 当前闭环是断的。** 预测侧已切亚盘（`BaselinePredictionGenerationServiceImpl` 产 `PredictionTypeEnum.ASIAN`，`MODEL_VERSION=t306-asian-baseline-v3`），但 `SettlementWriter:83` 只放行 `SPORTTERY`，ASIAN 直接 `skipped()`；即使放开，`:100` 的 `getHandicapPick()==null` 检查还会再拦一次。→ ASIAN 预测永远停在 LOCKED。`MarketTypeEnum` 仅 `HAD`/`HHAD`，全项目 `PredictionTypeEnum.ASIAN` 在 settlement 包中零出现。
- **当前"模型"实为水位比较器**：`homeOdds<=awayOdds ? HOME_COVER : AWAY_COVER`；`handicapLine`/`totalLine` 只用于生成说明文字，不参与计算。
- **v1 亚盘资产已完整（约 90%）**：`AsianOddsProvider` 接口、`TheOddsApiProvider`（完整实现，`MARKETS="spreads,totals"`、`REGIONS="eu"`、含重试+quota+单测）、`asian_odds_snapshots`（handicap_line/home/away + total_line/over/under）、`AsianOddsSyncService`/`SnapshotWriter`/`PayloadMapper`/`SyncJob`、发布锁定哈希快照。`MatchResultFact` 有 `homeScore`/`awayScore`，`SettlementCalculationSupport.requireFinalScore` 可取比分。
- **竞彩侧反向对照**：`sporttery_pool_snapshots` 表 + 六 SP 字段 + `SportteryProvider` 接口 + `PredictionImportServiceImpl` 的 SPORTTERY 校验（三概率=1±1e-6、handicapPick 非空、expectedTotalGoals 0~999.99）全部保留。若接竞彩源，只缺 Provider 实现 + 三分生成器；但用户最终选择亚盘，理由是亚盘/大小球接近 50/50、edge 信噪比高。
- **产出 `docs/asian-model-design.md`**，核心设计：
  - 统一联合进球分布 `P(h,a)=Pois(λh)·Pois(λa)`，让球与大小球是同一分布的两个投影，只需估 2 个参数。
  - λ 用**两市场联合反解**（网格搜索 + 局部细化），残差超阈值判定"市场自相矛盾"→ 该场不预测。这使模型概率不是单一市场的复述。
  - 主盘 = **使两边去水概率最接近 50/50 的线**（非众数）；实测三次命中 Pinnacle；反例：阿森纳场众数 -1.5(7家) 但真盘 -1.25(2家)。
  - 去水顺序硬规则：逐家去水 → 取中位 → 再归一。
  - push 处理：约束用 `p_win/(p_win+p_lose)`（条件于不 push），结算单独处理走盘。
  - **选择性发布**：`|model-market| < MIN_EDGE(0.02)` 不发布；"每场都发"与"期望为正"矛盾。
  - 结算统一 margin 模型：让球 `(h-a)+line`，大小球 `(h+a)-line`；.25/.75 拆两半；收益表 WIN/HALF_WIN/PUSH/HALF_LOSS/LOSS。

- **补充设计决策（4.10 不按联赛拆模型）**：结论是不拆。关键区分「结构差异 → 策略模式」vs「参数差异 → 同一结构+层次模型收缩」。联赛差异属后者。样本量论据：一赛季 5 联赛 + 欧冠约 1941 场 / 3882 个预测，选择性发布后实际 800~1200 条，按联赛独立拆分每个仅 130~240 条，参数/样本比 <5；层次模型（全局 3 + 6 个联赛偏移收缩）约 9 参数、样本/参数约 90~130。且 P1~P3 的 λ 是每场从市场反解、无拟合环节，此时不存在可分的"联赛参数"。真正需要多实现的只有三类且与联赛无关：加时赛制、中立场（用 `neutralVenue` 布尔置 homeAdv=0 即可）、数据源（已由 `AsianOddsProvider` 策略覆盖）。现在该做的是把联赛做成 yml 配置（`min-bookmakers` / `min-edge` / `enabled`），留扩展点而不写分支。
- **补充设计决策（4.11 预测/推荐/统计口径）**：
  - 四概念分离：预测（全量记录）、推荐（子集策略）、置信度（估计可信度）、edge（期望来源）。**决定期望的是 edge 不是置信度**；"高置信度 + 小 edge"是典型陷阱——市场共识确定但自己无优势，期望恰为 −抽水。
  - 竞彩 = 全量预测 + 全量公开的记录角色（三选一、抽水高，不宜对外推荐）；亚盘/大小球 = 选择性推荐角色。两者 ROI 不可混算。
  - **致命陷阱：事后按置信度筛选算 ROI = post-hoc selection，必然虚高且不可复现。** 必须区分探索性分析（仅生成假设）与验证性统计（阈值事前固定 + 滚动前推 walk-forward）。工程保障：`edge`/`model_prob`/`market_prob`/`confidence` 全冻结不可变，事后调参回算在数据层做不到。
  - 多重比较：一天 50 场、α=0.05 即使全噪声也有 2~3 场"显著" → 需 `max-per-day`（初值 5）+ 事前固定 `min-edge` / `min-confidence`，按 edge 降序取 Top-N；无达标场次就空仓。
  - 统计分层：L1 模型质量（Brier，**必须全量**）、L2 策略表现（ROI，**仅事前规则子集**）、L3 探索分桶（标注样本量，<30 不展示结论）、L4 CLV（几十场即可看出方向，样本不足期唯一能提前判真的指标）。
  - **配额硬约束（新发现）**：取收盘价需每日 odds 抓 2 次 → 5 联赛 × 2 markets × 2 次 = 20 credits/天 = 600/月，加 scores ~150/月 ≈ **750/月，免费档 500 不够**。三条出路：CLV 先单联赛试点（约 270/月）、上 $30 档、或关键联赛双抓其余单抓。推荐单联赛试点——CLV 的价值本就是小样本判真。
  - edge 概念澄清（已答用户）：`edge = model_prob − market_prob`（百分点），非赔率；`EV = p_model × odds − 1`。1.95 盘口抽水 2.56%，盈亏平衡 edge = 0.025/1.95 ≈ **1.28%**，这是 `MIN_EDGE=0.02` 的推导来源；edge 5% 时收益率 7.25%（赔率≈2 的放大效应）。
  - **用户主张「只有结算期望有意义」→ 回应并被采纳为核心原则**：确认最终验收权只归 L2 实测 ROI。补充关键恒等式：`p_close(去水) ≈ p_true` ⇒ `EV = p_true×o_buy−1 ≈ p_close×o_buy−1 = CLV`，即 **CLV 与期望收益理论上相等，只是估计效率不同**（ROI 需数千场，CLV 数十~数百场）。已推导 ROI 样本量：赔率 1.95、真实胜率 52%（edge≈1.4%）时 σ≈0.97，95% CI 半宽压到 2% 需 `n≈(1.96×0.97/0.02)²≈9000` 场。同时诚实标注 CLV 前提：依赖「收盘价≈真实概率」，流动性差的联赛不成立，这是优先做主流联赛的又一个理由。
  - **概念澄清（已答用户「EV 是否只对历史有意义」）**：EV=Expected Value=数学期望，属**事前/总体**概念，天然关于未来重复实验；实测 ROI 只是它的一个带噪估计量。四层结构：真实 EV（不可观测）← 模型 EV（事前估）/ 实测 ROI（事后估）/ CLV（用市价估）。用户担心的「历史统计凭什么指导新比赛」成立，但那是**统计历史命中率**这条路的缺陷，不是 EV 的缺陷：标量命中率无法算新比赛，参数 λ 可以。→ 已在文档新增 **4.12「为什么估参数而非统计历史命中率」**，含能力边界对照表 + 两个前提（泊松结构正确、生成机制稳定，后者用时间衰减应对）。
  - **表述纠正（用户质疑「你说模型 EV 没用？」）**：此前「模型 EV 会骗你」表述过绝对。准确说法 = **不能自证，但必须用于决策**。决策用途（算出来决定发不发）有效且必须；验证用途（用模型 EV 证明模型好）是循环论证。二者对应科学方法里的「假设可提出、检验须独立」。完整闭环：模型 EV（事前假设）→ 发布下注 → 结果 → 实测 ROI（事后检验）→ 修正模型。需警惕的唯一做法是「用模型 EV 的数字替代实测 ROI 的数字」。用户所说「看长期胜率+盈亏比算期望」= 实测 ROI = 最终验收，完全正确（亚盘中赔付结构由赔率决定，更准确说是「胜率+平均赔率」）。已补入文档 4.12.1。
  - **三阶段分工（文档 4.12.2）**：预测（赛前，市场赔率→去水→主盘→反解 λ，产出**概率**）→ 决策（赛前，模型概率 vs 市场概率，产出 edge/模型 EV，决定发不发）→ 评估（赛后，产出实测 ROI / CLV / Brier）。**关键：CLV 不参与预测**——它依赖收盘赔率，而收盘价在预测发布之后才形成，用它做预测等于时间倒流。CLV 唯一反向用途是修正模型（某类场景 CLV 系统性为负 ⇒ 模型有偏），属反馈不是输入。
