## 纠正：NovaAPI 有历史赔率（`/nova/tf/odds-history`）

用户追问「接口文档也没有吗」。**我上一轮说「NovaAPI 没有历史赔率」是错的** ——
`docs/data-sources-novaapi.md` 接口清单里早就记着 `/nova/tf/odds-history`，是我自己漏了。

### 实测结论

| 项 | 结果 |
|---|---|
| 端点 | `GET /nova/tf/odds-history`，入参 `idEvent` / `matchId` / `bdMatchId` 三选一 + 可选 `providerId` / `marketId` |
| 返回 | `providers[].markets[].options[].points[]`，point = `{odd, updateTime}` 升序 |
| 性质 | **变动快照**（非定时采样）。取「≤T 最后一条」= T 时刻**精确**价格（分段常值），不是近似 |
| 回溯深度 | 约 **4 个月**：06-20 / 07-01 / 07-15 / 08-01 / 08-15 / 09-01 / 09-15 / 10-20 全有（150KB~432KB）；06-02 空体（106B） |
| 赛程回溯 | `/nova/sports-lottery/all-list?date=` 可查到 2026-06-01 |
| 数据量 | 9-15 那场让球+大小球累计 1300 个变动点，单选项 2~7 个 |

**结论：回测样本不需要「以后攒」，可按日期枚举历史赛程后逐场拉。** 这直接推翻了昨天「先做采集层」的优先级判断。

### 三个坑

1. **`matchId` 单参偶发上游 500**：`Failed to connect to /112.126.29.186:8080`。同一场换 `idEvent` 立即 200，且同刻 `/nova/tf/odds`、`/nova/tf/bookmakers` 均正常 → 不是参数问题，按可重试错误处理，**别当「该场无历史」**。
2. **多参数签名需按字典序全签**：`matchId=..&marketId=..` 返回 401，服务端列出参与验签的键 `[marketId, matchId]`。生产 `NovaApiClient` 已正确，探针未处理。
3. **探针产物目录每次新建**：`ls -t | head -1` 会取到最近那次（可能是不想要的 401 响应），多文件比对要用 `ls -S`。

### 顺带修了文档一处错

`docs/data-sources-novaapi.md` §3 原写「无法精确取开赛前 3 小时的价格」—— **这是错的**。
变动快照是分段常值函数，取 ≤T 最后一条就是精确值。真正的限制是「记录起点由上游决定」（今日场从 T-2 天起）。

### 接口文档的读法（已写进文档）

SPA 无 OpenAPI 端点，但字段定义内嵌 `assets/index-*.js`：
`grep -bo '__name:"tf-odds-history"'` 取**字节**偏移（含中文，字符偏移会错）→ 字节切片 →
提 `n=V([{param,...}])` 入参、`o=`/`a=`/`r=` 逐层返回字段。同 bundle 有 30+ 端点清单。

### 四条新事实

1. **决策时点必须显式固定**：同一场赛前不同时点给出**三种**结论（主队 → LOW → 客队 → LOW），
   而大小球全程稳定「大球 MEDIUM」。回测不定死「赛前 T 小时」，结果没有意义。
2. **`updateTime` 是北京时间，不是 UTC**。生产 `NovaApiOddsPayloadMapper.parseTime` 按 UTC 解释
   （注释称「仅用于诊断排序」），当前无害；但**回测做「captured_at < kickoff_time」无泄漏断言时必须
   按 `Asia/Shanghai`**，否则赛前 105 分钟会被算成赛前 585 分钟——断言照样过，时序全错。
3. **数据源赛前约 1h45m 停更**：平博最后变动 15:14:21，之后到 17:00 开赛无任何点。
   「收盘价」实际是 T-105min 价，不能声称拿到临场价，CLV 也只能算到这一档。
4. **大小球 1.81 仍是负期望**：模型 0.530510 < 盈亏平衡 0.552486（margin −0.0220），
   与 10-22 大小球整体实亏 `−1.730` 同型——方向对不等于划算。
