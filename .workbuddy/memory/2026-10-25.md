## 模板兜底（修正「孤儿 RUNNING」）+ 回测归档结论更正

**1. `ProviderSyncTemplate` 收尾兜底（已改）**

原实现只有 `catch` 包住 `fetcher.fetch()`；`savePayload`/`link` 在其外，异常直冒调度层，
Job 只打日志不改状态 → 记录永久 `RUNNING`。重构为：

- `persistAndParse(providerCode, dataType, run, fetchResult, parser)`：入库 → 关联 → 解析 → 收尾，
  只处理预期内的解析失败；
- `finishUnexpectedFailure(...)`：取数成功后的任何 `RuntimeException` → `finishFailed`，
  **并把 `retryCount`/`quotaCost` 写进运行记录**（否则失败轮次额度显示 0，会被误读成「一次请求都没发出去」）；
  连 `finishFailed` 也失败时 `addSuppressed` 后抛原异常，不吞真因。

新增用例 `payloadPersistenceFailureStillFinishesRunAsFailed`（`RawDataProviderSyncTemplateTest` 6→7 全绿）。

| | `raw_data_payloads` | 回测归档 |
|---|---|---|
| 语义 | 一次同步调用的原始响应（当前态） | 一场一序列的赔率变动全史 + 按 T 切好的截面 |
| 主键 | `(provider, data_type, request_key, payload_hash)` | `(provider, match_id)` + 抓取版本 |
| 用途 | 解析 / 取证 / 幂等 | 特征源 / 可重放 |

## 19:20 孤儿 RUNNING 清理 + 定时任务超时机制调研

**1. 5 条孤儿已就地改 FAILED**

`data_sync_runs` id 64/68/70/72/76（全是 `NOVA_API` / `ASIAN_ODDS`，started 17:29:57 ~ 18:33:56）

**2. 定时任务确实没有任何超时机制（三层都没有）**

- `@Scheduled` 注解本身只有 `fixedDelay`/`fixedRate`/`cron`，**没有 timeout 属性**；
- `SchedulingConfig` 只有一个 `@EnableScheduling`，未定制 `TaskScheduler` → Spring Boot 默认
  `spring.task.scheduling.pool.size=1`，**7 个 Job 挤在同一个线程**，一个卡住其余全部排队；
- HTTP 侧 `connect-timeout: 5s` / `read-timeout: 20s` 是 **socket 级**，不是整次同步的总时限。
  亚盘 29 场是 29 次串行调用，最坏 `29 × (25s×2 重试 + 0.5s)` ≈ 24 分钟，已超过 `fixed-delay: 20m`；
- **没有「启动时把遗留 RUNNING 收尾」的逻辑**（三个 `ApplicationRunner` 都与 sync run 无关），
  进程被强杀/重启后那条记录永久停在 RUNNING；
- `DataSyncRunServiceImpl.finish` 用 `getById` + `updateById`，**不是 `WHERE sync_status='RUNNING'` 的条件更新**，
  也无心跳列（只有 `started_at`），管理端无法区分「真在跑」与「上次进程崩了」。

本次这 5 条属于**异常逃逸型**（fetched/success/failure 全 0、`error_message` 为 null → `finishFailed` 从未执行），
已由模板兜底修复；**进程崩溃型**（强杀、OOM、IDEA 重启）仍无自愈，是遗留风险。

**3. 建议（未实施）**：`SyncRunRecoveryRunner` 在启动时把 `started_at < now - 30min` 的 `RUNNING`
批量置 FAILED（reason=`STALE_RUN_RECOVERED`），并在每个同步 Job 起始处再扫一次；比给任务加超时更划算——
进程内无法真中断阻塞 IO，超时线程池只会制造「假失败 + 真还在写库」。

## 19:38 两个真 bug：自动发布任务从未创建、首页主盘取错行

  与其余七个任务一致。守卫用例 `PredictionAutoPublishJobWiringTest`（断言无 `@Component` + `@Bean` 形态）。

  **21 场至少一个市场有方向**，只有 2 场 `INCONSISTENT_ASIAN_MARKETS`(邻线)、1 场 `MARKET_DISPERSION_TOO_HIGH`。
  即「全是 LOW 所以不发」这个先前猜测是错的——生成根本没跑过。
- 修复后实测（19:37）：`candidates=29 generated=14 inserted=14 published=14 failed=0`，
  `skipped={NOT_SCHEDULED=4, KICKOFF_PASSED=2, INCONSISTENT_ASIAN_MARKETS=2, MARKET_DISPERSION_TOO_HIGH=1}`。
  14 条全部 `PUBLISHED`，冻结行全部 pinnacle，`edge_cover`/`edge_over` 全 `0.000000`（正常）。

**2. 首页「亚盘主盘」取的是交叉积里最后写入的一行，不是主盘**

- 现象：005 显示 `+0.5 主 1.48 / 客 2.41`（真实主盘 `0`，pinnacle 2.00/1.91）；006 显示 `-2.5 主 3.2 / 客 1.29`
  （真实主盘 `-1.5`）。两场都恰好是 betvictor 在交叉积里的最后一行。
- 根因：`MatchQueryServiceImpl.loadLatestAsianMainMarkets` 用
  `selectLatestCompleteLinesByMatchIds`（`DISTINCT ON (match_id) ORDER BY captured_at DESC, id DESC`），
  即「整场最新一条」。落库是 (让球线 × 大小球线) 交叉积，最新一条与「哪条线最平衡」毫无关系。
- 修复：改为取 `selectLatestCrossProductLinesByMatchIds`，再用**生成侧同一套**
  `AsianMarketConsensusAggregator` + `AsianFreezeSnapshotSelector` 算共识主盘并落到真实行。
  首页展示的线必须等于模型决策并结算的那一行，否则两套线会分裂。
  共识线上没有完整行时该场不显示亚盘（宁可空，也不显示不会用于决策的线）。
- 实测：005 → pinnacle `0.0` 主 2.00/1.91、大小球 2.75；006 → pinnacle `-1.5` 主 2.00/1.91、大小球 3.25。

**3. 启动自愈（本次新增）**

`SyncRunRecoveryService` + `SyncRunRecoveryRunner`：`ApplicationRunner` 在启动时把
`started_at < now - 10min` 的 `RUNNING` 批量置 `FAILED`（`STALE_RUN_RECOVERED`）。
阈值 10 分钟只为多实例共存时放过「另一实例刚创建的行」；不放 `@Scheduled` 里是因为调度线程池
只有一个线程，卡住时恢复任务自己也会排队。恢复失败只记 WARN，不阻止启动。

## 19:55 前端预测卡片重排：结论优先

用户反馈「预测结果排版很奇怪」，并给出需求：最需要的是一条结论，形如「主-0.5 大2.5」。

**病因**：块内 8 行文字同字号同色，结论混在推导里；且「模型 53.0% / 市场 53.0% / edge 0.0%」
在当前模型下**是恒等式**（λ 由该主盘去水概率反解、再投影回同一条线必然相等），零信息却占三分之一版面，
还容易被读成「模型没优势」。

**改法**
- 新增 `features/matches/PredictionVerdictLegs.tsx`（列表页与详情页共用，用结构类型约束避免两套实现走偏）：
  两格并排，格内 `方向+盘口线` 19px 加粗为主角（`主 -0.5`、`客 +1.5`、`大 2.5`），
  赔率与置信度降为副行；置信度用轻量色标（绿/黄/灰），不用高饱和色块。
- `matchPresentation.ts` 拆出 `asianHandicapVerdictText` / `totalGoalsVerdictText` / `formatAsianLine`：
  平手盘写「平手」不写 `0`（「主 0」会被读成不存在的受让 0 球）；`formatAsianHandicapLine` 改为导出 `formatAsianLine`。
- 卡片顺序改为 `预测结果 → 亚盘主盘 → 体彩赔率`；预测块加浅色高亮边框（它是主内容，另两块是依据）。
- 模型概率 / edge / λ / σ / 判定行收进 `<details>模型诊断与判定行`，默认折叠。
- 空方向不再留空，写明「无方向 / 未达发布门槛」；`.prediction-leg-verdict` 锁 `min-height: 22px`
  让同一行三张卡片在「亚盘主盘」处对齐（空方格字号更小，不锁就会错开 ~5px）。
- 顺带统一「亚盘主盘」文案：`亚洲主队 -1` → `让球 -1`（同走 `formatAsianLine`）。
