## 回测详情页白屏（`/admin/backtest/6`）

用户报「这个页面报错」。三个接口（`progress` / `compare` / `cases`）全部返回 `SUCCESS`，
所以不是接口坏，是渲染时抛异常被 `AppErrorBoundary` 接住 → 整页变成错误页。

**定位方式**（值得复用）：给页面写一个临时 vitest 用例，mock `adminSession` + `fetch`
喂**真实接口响应**（curl 存成 json 再 `readFileSync`），用 `MemoryRouter` 渲染。
第一次跑就复现：`TypeError: Cannot convert undefined or null to object`
→ `BacktestMetricsTable.tsx:140` 的 `Object.keys(metrics.skipReasonCounts)`。

**根因**：又是 `@Select` 绕过 `autoResultMap`。`backtest_metrics` 的
`skip_reason_counts` / `metrics_json` 两列读回 `null`，而写库正常（MP 的 insert 用 typeHandler），
所以库里一直有值、接口一直返回 null。这是同一个坑的第二次（第一次是归档 `payload`）。

修法：`selectByRunId` 从 `@Select` 改成 default 方法里的 `selectList(wrapper)`，
排序（`group_key` + `ALL→让球→大小球`）挪到内存（上限 8×3）。
`BacktestMetricsMappingTest` 用反射钉住「不许改回 `@Select`」「不许删 typeHandler」——
两件事都不会让编译失败。

**同一次排查还发现三处类型/显示错误**：
- `BacktestResultStatus` 前端写 5 个值（`PENDING|SETTLED|VOID|NO_RESULT|FAILED`），
  后端只产生 3 个（`PENDING|FINAL|VOID`）——真实值 `FINAL` 反而不在集合里，且无编译报错。
- `skipReasonCounts` 类型声明成非空，实际是 null → 下游忘记判空。
- 逐场明细的 λ（期望进球 1.96/1.11）用 `formatProbability` 渲染成「196.1%/111.0%」。

提交 `76e383a`。后端 852 项（+2）、前端 104 项（+3）、`tsc -b`、`vite build` 全绿。

## 顺带查清样本利用率只有 40% 的原因

十月全月 baseline 80 场的交叉统计（用真实 `cases` 响应跑 python）：

```
INFEASIBLE  → INCONSISTENT_ASIAN_MARKETS   44
DECIDED     → null                         32
BOTH_MARKETS_REJECTED → LOW_CONFIDENCE      3
BOTH_MARKETS_REJECTED → MARKET_DISPERSION   1
```

**44 场「两市场不自洽」全部是 λ 解不出来（`INFEASIBLE`），没有一场是真的残差或邻线超限。**
`INCONSISTENT_ASIAN_MARKETS` 的两个出口在逐场明细的「判定阶段」列能分开，
但在汇总的跳过分布里分不开 —— 看分布会误以为「市场在打架」。

`ImpliedPoissonModel` 有四种不可行（`INVALID_INPUT` / `TOTALS_PROBABILITY_OUT_OF_RANGE` /
`LAMBDA_SPLIT_IMPOSSIBLE` / `HANDICAP_PROBABILITY_OUT_OF_RANGE`），**这个原因目前没落库**，
所以连「44 场里各是哪种」都查不到。这是数据缺口，也是下一步该做的诊断。
