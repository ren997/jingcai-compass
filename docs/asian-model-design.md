## 1. 为什么只做让球与大小球

这是本项目唯一能自证价值的市场形态，理由不是偏好，而是数学：

| 市场 | 典型赔率 | 去水隐含概率 | 2% 概率误差的相对价值 |
|---|---|---|---|
| 竞彩胜平负（热项） | 1.30 | 75% | 低：需击败 25% 的抽水空间 |
| 竞彩胜平负（冷项） | 8.00 | 12% | 低：方差过大，需极多样本 |
| **亚盘让球** | **1.85 ~ 2.05** | **~50%** | **高：2% 偏差即 4% 相对优势** |
| **大小球** | **1.85 ~ 2.05** | **~50%** | **高：同上** |

两个结论：

1. **接近 50/50 的市场才有可辨识的 edge。** 赔率越接近 2.0，`edge / 抽水` 的信噪比越高；高水项需要极长样本才能区分"模型有信息"与"运气好"。
2. **让球与大小球是同一个分布的两个投影。** 二者都能由联合进球分布 `P(h, a)` 推出，因此可以用**一个模型同时服务两个市场**，参数只有 2 个，小样本下不易过拟合。

竞彩线路保留在 v1 现状即可（`HAD`/`HHAD` 结算器仍在），不在本方案范围内。

// 方向：谁水位低押谁

## 4. 模型设计

### 4.1 总体思路：一个分布，两个投影

设一场比赛主队进球 `h`、客队进球 `a`，联合分布近似为

```
P(h, a) = Pois(h; λh) × Pois(a; λa)
```

所有目标市场都是这个分布的投影：

| 市场 | 判定量 | 概率表达式 |
|---|---|---|
| 让球（主队 line = H，H 为负数表示主队让球） | `margin = (h − a) + H` | `P(margin > 0)` 赢盘，`= 0` 走盘 |
| 大小球（line = L） | `total = h + a` | `P(total > L)` 大球，`= L` 走盘 |

因此**不需要分别训练两个模型**，只需估计 `(λh, λa)`。这是本设计最重要的简化：参数从"每个市场一套"降到全局 2 个，样本效率提升一个量级。

### 4.2 λ 的估计：从市场概率反解

第一版没有多年历史样本，不能做 MLE 训练。正确做法是**从市场反解**，但不是简单去水，而是**用两个市场联合约束**：

```
已知（去水后、条件于不 push）：
  p_cover = 主队赢盘概率
  p_over  = 大球概率

求 (λh, λa) 使：
  f1(λh, λa) = P((h − a) + H > 0) + push归零处理 = p_cover
  f2(λh, λa) = P(h + a > L)                  = p_over
```

两个方程、两个未知数。求解方式：

1. `λ` 搜索域 `[0.20, 4.00]`，步长 `0.01`，粗网格（约 145k 组合，单场毫秒级）
2. 目标函数为两个方程的加权平方残差
3. 取最小残差点后，在其邻域内步长细化到 `0.001`
4. **残差超过阈值则判定"市场自相矛盾"，该场不预测**

第 4 点是设计的一部分，不是兜底：若亚盘与大小球隐含的 λ 不一致，说明两个市场定价冲突或数据有问题，此时任何"预测"都是噪声。

> 这一步得到的 `(λh, λa)` **不是任何一个单一市场的复述**。它是两个市场的联合估计，当两个市场出现分歧时，解会向两者之间的某个点收敛。这是相对于"直接去水"的第一个真实信息增益。

### 4.3 push 与四分之一盘的处理

去水时按三向归一（赢 / 走 / 输），但**约束方程使用"条件于不 push"的概率**：

```
p_cover = p_win / (p_win + p_lose)        // 排除走盘
```

理由：走盘退本金，不携带方向信息。若把走盘按 0.5 计入，会把 λ 估计拉偏。结算时走盘单独处理（见 5.2）。

主盘偏好顺序（按可获得性）：

1. **x.5 半盘**（无走盘，模型与结算都最干净）
2. x.25 / x.75 四分之一盘（拆两半）
3. 整数盘（有走盘，仅在无其他选择时使用）

### 4.4 主盘选择：不是"取众数"

同一场比赛各家报价的盘口可能相差一整球（实测英超出现过 `-1.0 / -0.5 / -0.25 / 0.0` 并存）。

**主盘定义：使两边去水概率最接近 50/50 的那条线。** 这是亚盘"标准盘"的本义。

在真实数据上验证过三次，全部命中 Pinnacle：

| 比赛 | 各家报的线 | 选出 | Pinnacle 实际 |
|---|---|---|---|
| 阿森纳 vs 埃弗顿 | -1.5(7家) / -1.25(2家) | -1.25 | -1.25 |
| 维拉 vs 曼城 | 0.5 / 0.75 / 1.0 / 1.5 | 0.75 | 0.75 |
| 利物浦 vs 布莱顿 | -1.0 / -0.5 / -0.25 / 0.0 | -0.25 | -0.25 |

注意第一行：**众数在 -1.5（7 家），但真盘是 -1.25（仅 2 家）**。取众数会系统性偏离真盘 0.25 球，长期直接损耗 ROI。

约束：`bookmaker_count < 2` 的市场不生成预测（让球盘报价家数天然少，实测 18 家中仅 8 家报 spreads）。

### 4.5 赔率聚合顺序

```
1) 逐家去水：p_i = (1/price_i) / Σ(1/price_j)      ← 先按单家归一
2) 对 p_i 取中位数 → p̄
3) 再归一一次
```

**顺序不可颠倒。** 先取中位赔率再去水，会被单个异常报价（错价、延迟更新）带偏；先逐家去水再取中位，可以抵抗离群值。

### 4.6 离散度作为置信度信号

对每个市场计算各家去水概率的标准差 `σ`：

- `σ` 小 → 市场高度一致，定价可信，模型输出的参考价值高
- `σ` 大 → 分歧严重，通常伴随信息不对称或临场变化

用途不是"预测"，而是**过滤**：`σ` 超过阈值直接降低置信度或跳过该场。这是市场共识本身不包含的信息。

### 4.7 选择性发布：正期望的必要条件

这是本方案与当前实现最大的行为差异。

```
edge = model_prob − market_prob
若 |edge| < MIN_EDGE（初值 0.020），不生成该方向预测
```

理由：若模型输出等于市场共识，发布出去就是**承担抽水后的零 EV**，长期必然为负。**"每场都发"这件事本身与"期望为正"矛盾。**

代价是覆盖率下降（多数场次不发），但这正是"只在有信息时才说话"的必然结果。统计页的 `已发布场次` 会显著少于 `已同步场次`，这是设计意图，不是故障。

### 4.8 校准与评估

| 指标 | 定义 | 说明 |
|---|---|---|
| `model_brier` | `mean((model_prob − outcome)²)` | 按市场分别统计 |
| `market_brier` | 同上，用去水市场概率 | **必须并列展示**，否则无法判断模型是否优于市场 |
| 可靠性曲线 | 按 `model_prob` 分 10 桶，桶内实际命中率 | 斜率应接近 1 |
| CLV | 发布时赔率 vs 收盘赔率 | 若能取到收盘价，这是最敏感的早期信号 |
| ROI | `Σ profit / Σ stake` | 只统计已发布场次 |

**验收硬标准：`model_brier < market_brier`。** 达不到就说明模型没有产生信息，无论统计页多好看。

### 4.10 为什么不按联赛拆分策略与模型

结论：**第一版不拆，P4 之后用层次模型而不是策略模式，只在"结构差异"出现时才引入多实现。**

#### 4.10.1 关键区分：结构差异 vs 参数差异

| | 结构差异 | 参数差异 |
|---|---|---|
| 定义 | 计算方式不同、输出语义不同 | 同一套计算，系数不同 |
| 例子 | 不同市场的结算规则（让球 vs 大小球）<br>不同数据源的解析协议<br>不同产品类型的字段契约 | 各联赛的进球率、主场优势强度<br>各联赛的赔率效率（抽水比例） |
| 正确表达 | **策略模式 / 多实现** | **同一结构 + 不同参数（层次模型）** |

联赛之间的差异几乎全是**参数差异**。用策略模式表达参数差异，是把统计问题错解成代码问题——代码看起来扩展性好，实际每个分支都在拿一小撮数据独立拟合，方差爆炸。

> 本项目已经有正确的策略模式用例，可以作为对照：`MarketSettlementCalculatorRouter` 按 `MarketTypeEnum` 路由结算器、`AsianOddsProvider` 按数据源切换实现。这两个拆分的理由是**计算规则本身不同**，而不是"配置不同"。

#### 4.10.2 数学原因：样本量不允许

一个赛季的场次（含两个市场，每场最多 2 个预测）：

| 联赛 | 场次/赛季 | ×2 市场 |
|---|---|---|
| 英超 | 380 | 760 |
| 西甲 | 380 | 760 |
| 意甲 | 380 | 760 |
| 德甲 | 306 | 612 |
| 法甲 | 306 | 612 |
| 欧冠 | ~189 | ~378 |
| **合计** | **1,941** | **~3,882** |

叠加 4.7 的选择性发布（`MIN_EDGE = 0.02`，实际发布率约 20%~30%），**真实可用样本约 800~1,200 条**。

若按联赛拆成 5~6 个独立模型，每个模型只有 **130~240 条样本**。用这个量级去估"该联赛自己的 λ 基线 + 主场优势 + 阈值"，估出来的参数标准误远大于联赛间真实差异，等于把噪声固化进代码。

参数数量对比：

| 方案 | 参数规模 | 样本/参数 |
|---|---|---|
| 每联赛独立模型（含球队攻防） | 6 × 20 队 × 2 ≈ 240+ | < 5 ❌ |
| 每联赛独立模型（仅联赛基线） | 6 × 3 = 18 | ~50 ⚠️ |
| **层次模型（全局 + 联赛偏移收缩）** | 全局 3 + 6 偏移 = 9 | **~90~130 ✅** |

#### 4.10.3 第一版根本没有"训练"这个环节

必须说清楚：**P1~P3 的 `(λh, λa)` 是每场从市场现算的**（见 4.2），不涉及任何拟合，也就不存在"联赛参数"这个东西。

一场英超和一场西甲，反解算法、去水顺序、主盘选择规则完全相同；输入不同自然得出不同的 λ。**此时按联赛分模型没有任何可分的对象。**

只有到 P4 引入历史先验（Dixon-Coles），才第一次出现"需要估计的联赛级参数"——而那时正确的做法是层次模型：

```
λ_home = exp(μ + homeAdv + attack[home] − defence[away] + leagueOffset[league])
λ_away = exp(μ + attack[away] − defence[home] + leagueOffset[league])

leagueOffset ~ Normal(0, σ_league)     ← 部分汇聚：样本少自动收缩向 0
```

`σ_league` 由数据估计。若联赛间确实差异显著，`σ_league` 大，偏移保留；若差异只是噪声，`σ_league` 小，偏移自动收缩到 0。**这个判断由数据做，而不是由开发者拍脑袋写 if-else。**

这也意味着：如果将来发现某联赛确实需要独立参数，层次模型会自动给出——不需要改代码，只需要重新拟合。

#### 4.10.4 什么情况下**才**该引入多实现

只有这三类，且都与"联赛"无关：

1. **赛制结构不同**：涉及加时/点球的赛事（结算规则不同）。当前所有目标市场均为 90 分钟口径，不涉及。若将来做杯赛让球，需单独计算器。
2. **中立场**：欧冠决赛、超级杯等无主场优势。用一个 `neutralVenue` 布尔参数把 `homeAdv` 置 0 即可，**不需要新模型**。
3. **数据源不同**：不同 provider 的字段与协议不同 —— 已由 `AsianOddsProvider` 策略覆盖。

#### 4.10.5 那么现在该做什么

不是"什么都不做"，而是**把联赛做成配置而不是常量**，为将来留出扩展点：

```yaml
app.asian-odds:
  leagues:
    - key: soccer_epl
      display-name: 英超
      enabled: true
      min-bookmakers: 2          # 数据质量门槛，可按联赛收紧
      min-edge: 0.020            # 赔率效率高的联赛可提高阈值
    - key: soccer_uefa_champs_league
      display-name: 欧冠
      enabled: false             # 待 M0 补验 scores 覆盖
      min-bookmakers: 3          # 欧战报价家数更多，门槛可提高
```

这样做的价值：**当数据证明某联赛确实需要不同处理时，改配置即可，不改代码**。而如果过早写成策略模式，等发现"其实差异不显著"时，那些分支会变成必须维护的死代码。

#### 4.10.6 一句话总结

> 联赛差异用**参数**表达，市场与数据源差异用**策略**表达。前者交给收缩估计，后者交给接口。把前者写进 `switch`，等于用代码固化一个尚未被数据验证的假设。

## 5. 结算设计

### 5.1 统一 margin 模型

```
让球：margin = (homeScore − awayScore) + handicapLine
大小球：margin = (homeScore + awayScore) − totalLine

margin > 0 → 赢
margin = 0 → 走
margin < 0 → 输
```

验算：阿森纳让 -1.25，1:0 胜 → `margin = 1 − 1.25 = −0.25` → 拆 `−0.5`（输）+ `0`（走）→ **半输**。即"让一球/球半，赢一球输半"，正确。

### 5.2 拆盘与收益

| 小数部分 | 处理 |
|---|---|
| `.5` | 半球盘，无走盘 |
| `.0` | 整数盘，`margin = 0` 走盘 |
| `.25` / `.75` | 拆为 `line − 0.25` 与 `line + 0.25` 两个半盘分别判定 |

合并规则：

| 两个半盘 | 结果 | `stake = 1` 时净收益 |
|---|---|---|
| 赢 + 赢 | `WIN` | `price − 1` |
| 赢 + 走 | `HALF_WIN` | `(price − 1) / 2` |
| 走 + 走 | `PUSH` | `0` |
| 输 + 走 | `HALF_LOSS` | `−0.5` |
| 输 + 输 | `LOSS` | `−1` |

### 5.3 SettlementWriter 分派

```
prediction_type = SPORTTERY → 现有路径（HAD / HHAD），不动
prediction_type = ASIAN     → 新路径（ASIAN_HANDICAP / ASIAN_TOTAL_GOALS）
    两个市场分别独立结算，一个方向为空则不结算该市场
    不要求 handicapPick（三向枚举）非空
```

现有 `SettlementWriter:100` 的 `getHandicapPick() == null` 检查必须改为**仅对 SPORTTERY 生效**，否则 ASIAN 会在第二道闸门再次被拦。

幂等仍由既有机制保证：先按 `(prediction_id, market_type, is_current)` 查已有当前结算，存在即跳过；重跑不产生重复行，`profit` 不变。

## 7. 分阶段实施

| 阶段 | 内容 | 验收 |
|---|---|---|
| **A. 结算闭环** | 市场枚举 + 2 个计算器 + SettlementWriter 分派 | 构造 5 种盘口（半球/整数/四分之一 × 赢输走）矩阵测试全通过；重跑幂等 |
| **B. 聚合与主盘** | 逐家去水、中位数、最平衡线选择 | 用真实响应 fixture 验证三次主盘选择命中 Pinnacle；`count < 2` 正确跳过 |
| **C. λ 反解模型** | 网格搜索 + 概率投影 + 残差过滤 | 给定 `(p_cover, p_over)` 能反解出 λ 并回投出与输入一致的概率（往返误差 < 1e-4） |
| **D. 选择性发布** | edge 阈值 + 离散度过滤 | 人为构造"模型=市场"的输入 → 不生成预测 |
| **E. 概率落库与统计** | V22 迁移 + 统计页并列双 Brier | 统计页同时展示 `model_brier` 与 `market_brier` |

A 与 B/C 可并行。**A 优先**，因为没有结算，模型再好也无法验证。

## 8. 风险与未决

### 8.1 已知风险

| 风险 | 影响 | 应对 |
|---|---|---|
| 让球盘报价家数少（实测 8/18） | 中位数不稳定 | 门槛设为 2 家，并落库 `bookmaker_count`，统计时可按家数分层 |
| 两市场无解 | 该场无法预测 | 残差阈值过滤，记录跳过原因，计入健康指标 |
| 主盘与真盘仍可能偏离 | 结算口径与实际下注盘口不一致 | 落库实际使用的 line，允许事后审计 |
| 选择性发布导致覆盖率低 | 用户观感"没什么可看" | 前端明确区分"今日可分析"与"今日无优势"，不隐藏 |

### 8.2 必须承认的边界

**第一版模型的概率仍然源自市场。** 它比"押低水方"强，因为做了联合估计与去水，但它不是独立于市场的预测。因此：

- 在与市场对比的 Brier 上，第一版**可能只是略优或持平**
- 真正的信息增益要等 P4（Dixon-Coles 先验）与 P5（赔率漂移）
- 在此之前，统计页必须如实标注"模型概率由市场反解，不构成独立预测"

### 8.3 待确认

1. **报价区域**：当前 `TheOddsApiProvider` 固定 `REGIONS = "eu"`。是否加 `uk`（覆盖 Pinnacle / Betfair 更全，但每联赛 +1 credit）？
2. **联赛范围**：沿用 v2 方案的五联赛（英超/西甲/意甲/德甲/欧冠），还是先单联赛跑通？
3. **比分来源**：继续使用现有体彩赛果链路，还是改接 The Odds `scores`（同源 event id，无映射成本，但 +2 credits/联赛）？
4. **`MIN_EDGE` 初值**：0.020 是保守取值，会让发布量很少。是否先设 0.010 观察一段时间再收紧？
