## 1. 为什么只做让球与大小球

这是本项目唯一能自证价值的市场形态，理由不是偏好，而是数学：

| 市场 | 典型赔率 | 去水隐含概率 | 2% 概率误差的相对价值 |
|---|---|---|---|
| 竞彩胜平负（热项） | 1.30 | 75% | 低：需击败 25% 的抽水空间 |
| 竞彩胜平负（冷项） | 8.00 | 12% | 低：方差过大，需极多样本 |
| **亚盘让球** | **1.85 ~ 2.05** | **~50%** | **高：2% 偏差即 4% 相对优势** |
| **大小球** | **1.85 ~ 2.05** | **~50%** | **高：同上** |

两个结论：

1. **接近 50/50 的市场才有可辨识的 edge。** 赔率越接近 2.0，`edge / 抽水` 的信噪比越高；高水项需要极长样本才能区分"模型有信息"与"运气好"。
2. **让球与大小球是同一个分布的两个投影。** 二者都能由联合进球分布 `P(h, a)` 推出，因此可以用**一个模型同时服务两个市场**，参数只有 2 个，小样本下不易过拟合。

竞彩线路保留在 v1 现状即可（`HAD`/`HHAD` 结算器仍在），不在本方案范围内。

## 4. 模型设计

### 4.1 总体思路：一个分布，两个投影

设一场比赛主队进球 `h`、客队进球 `a`，联合分布近似为

```
P(h, a) = Pois(h; λh) × Pois(a; λa)
```

所有目标市场都是这个分布的投影：

| 市场 | 判定量 | 概率表达式 |
|---|---|---|
| 让球（主队 line = H，H 为负数表示主队让球） | `margin = (h − a) + H` | `P(margin > 0)` 赢盘，`= 0` 走盘 |
| 大小球（line = L） | `total = h + a` | `P(total > L)` 大球，`= L` 走盘 |

因此**不需要分别训练两个模型**，只需估计 `(λh, λa)`。这是本设计最重要的简化：参数从"每个市场一套"降到全局 2 个，样本效率提升一个量级。

### 4.2 λ 的估计：从市场概率反解

第一版没有多年历史样本，不能做 MLE 训练。正确做法是**从市场反解**，但不是简单去水，而是**用两个市场联合约束**：

```
已知（去水后、条件于不 push）：
  p_cover = 主队赢盘概率
  p_over  = 大球概率

求 (λh, λa) 使：
  f1(λh, λa) = P((h − a) + H > 0) + push归零处理 = p_cover
  f2(λh, λa) = P(h + a > L)                  = p_over
```

两个方程、两个未知数。求解方式：

1. `λ` 搜索域 `[0.20, 4.00]`，步长 `0.01`，粗网格（约 145k 组合，单场毫秒级）
2. 目标函数为两个方程的加权平方残差
3. 取最小残差点后，在其邻域内步长细化到 `0.001`
4. **残差超过阈值则判定"市场自相矛盾"，该场不预测**

第 4 点是设计的一部分，不是兜底：若亚盘与大小球隐含的 λ 不一致，说明两个市场定价冲突或数据有问题，此时任何"预测"都是噪声。

> 这一步得到的 `(λh, λa)` **不是任何一个单一市场的复述**。它是两个市场的联合估计，当两个市场出现分歧时，解会向两者之间的某个点收敛。这是相对于"直接去水"的第一个真实信息增益。

### 4.3 push 与四分之一盘的处理

去水时按三向归一（赢 / 走 / 输），但**约束方程使用"条件于不 push"的概率**：

```
p_cover = p_win / (p_win + p_lose)        // 排除走盘
```

理由：走盘退本金，不携带方向信息。若把走盘按 0.5 计入，会把 λ 估计拉偏。结算时走盘单独处理（见 5.2）。

主盘偏好顺序（按可获得性）：

1. **x.5 半盘**（无走盘，模型与结算都最干净）
2. x.25 / x.75 四分之一盘（拆两半）
3. 整数盘（有走盘，仅在无其他选择时使用）

### 4.4 主盘选择：不是"取众数"

同一场比赛各家报价的盘口可能相差一整球（实测英超出现过 `-1.0 / -0.5 / -0.25 / 0.0` 并存）。

**主盘定义：使两边去水概率最接近 50/50 的那条线。** 这是亚盘"标准盘"的本义。

在真实数据上验证过三次，全部命中 Pinnacle：

| 比赛 | 各家报的线 | 选出 | Pinnacle 实际 |
|---|---|---|---|
| 阿森纳 vs 埃弗顿 | -1.5(7家) / -1.25(2家) | -1.25 | -1.25 |
| 维拉 vs 曼城 | 0.5 / 0.75 / 1.0 / 1.5 | 0.75 | 0.75 |
| 利物浦 vs 布莱顿 | -1.0 / -0.5 / -0.25 / 0.0 | -0.25 | -0.25 |

注意第一行：**众数在 -1.5（7 家），但真盘是 -1.25（仅 2 家）**。取众数会系统性偏离真盘 0.25 球，长期直接损耗 ROI。

约束：`bookmaker_count < 2` 的市场不生成预测（让球盘报价家数天然少，实测 18 家中仅 8 家报 spreads）。

### 4.5 赔率聚合顺序

```
1) 逐家去水：p_i = (1/price_i) / Σ(1/price_j)      ← 先按单家归一
2) 对 p_i 取中位数 → p̄
3) 再归一一次
```

**顺序不可颠倒。** 先取中位赔率再去水，会被单个异常报价（错价、延迟更新）带偏；先逐家去水再取中位，可以抵抗离群值。

### 4.5.1 实测：抽水分层严重，不能无脑取全量中位数

2026-10-20 实测英超（`regions=eu`、`markets=spreads,totals`，20 场未开赛赛事，消耗 2 credits）：

| 指标 | 让球 spreads | 大小球 totals |
|---|---|---|
| 当前在盘赛事数 | 20 | 20 |
| 全部 outcome 赔率中位 | 1.94 | 1.91 |
| **主盘（最平衡线）赔率中位** | **1.935** | **1.913** |
| 主盘赔率均值 | 1.963 | 1.916 |
| **单边抽水中位** | **4.20%** | **5.56%** |
| 抽水 P10 ~ P90 | 1.42% ~ 7.95% | 2.89% ~ 8.76% |

**关键现象：抽水与报价家数呈反相关。**

| 样例 | 报价家数 | 抽水 |
|---|---|---|
| 让球 line = +0.25 | 2 | **1.67%** |
| 让球 line = +0.75 | 2 | 1.80% |
| 让球 line = −1.25 | 2 | 2.18% |
| 让球 line = −0.5 | 6 | 4.38% |
| 大小球 line = 2.5 | 17 | 5.42% |

原因：低抽水庄（Pinnacle、Matchbook）通常**只报主盘**，而 1xBet 这类高抽水庄会报几乎所有 line。因此「报价家数多」恰恰意味着「掺入了更多高抽水定价」。

**这推翻了一个朴素假设**：主盘赔率看起来约 1.93~1.96，但按全部 bookmaker 取中位数，实际承担的是 **4%~5.6% 抽水**，而不是 1.95/1.95 对应的 2.6%。

#### 设计影响

1. **聚合必须按庄家白名单，而不是全量中位数。** 优先 Pinnacle / Matchbook / Betfair 等低抽水源，`bookmaker_count` 门槛与"低抽水庄数量"要分开统计。
2. **`edge` 的盈亏平衡点随赔率变化**：赔率 1.935 时盈亏平衡胜率 51.68%，即所需 edge ≥ 1.68%；赔率 1.85 时需 ≥ 4.05%。固定 `MIN_EDGE = 0.02` 在实测抽水下仍处于亏损区，**发布门槛必须逐场按赔率计算**（见 4.7）。
3. **决策价格与评估价格必须一致。** 若用中位赔率算 edge、却按 Pinnacle 报价下注，或反之，ROI 与 CLV 都会失真。落库时必须记录实际用于计账的 `odds` 及其 `bookmaker_code`。

> 待确认项：是否需要为 `bookmaker` 建白名单配置（`app.asian-odds.bookmaker-whitelist`），以及是否记录每家的抽水以支持事后筛选。这条会影响 `AsianMarketOddsAggregator` 的实现形态。

### 4.6 离散度作为置信度信号

对每个市场计算各家去水概率的标准差 `σ`：

- `σ` 小 → 市场高度一致，定价可信，模型输出的参考价值高
- `σ` 大 → 分歧严重，通常伴随信息不对称或临场变化

用途不是"预测"，而是**过滤**：`σ` 超过阈值直接降低置信度或跳过该场。这是市场共识本身不包含的信息。

### 4.7 选择性发布：正期望的必要条件

这是本方案与当前实现最大的行为差异。

**发布条件按赔率动态计算，不使用固定阈值。**

市场去水概率 50% 并不等于盈亏平衡：盈亏平衡点由该盘口的实际赔率决定（推导见 4.11.2）：

```
盈亏平衡胜率   p_breakeven  = 1 / 赔率
要求           model_prob  >= p_breakeven + SAFETY
等价于         edge        >= (1/赔率 − market_prob) + SAFETY
```

其中 `(1/赔率 − market_prob)` 是**该盘口的抽水分摊**，`SAFETY` 是为模型估计误差预留的余量（初值 0.010）。

代入 4.5.1 的实测主盘赔率：

| 市场 | 主盘赔率中位 | 抽水分摊 | 所需 edge（SAFETY=0.010） |
|---|---|---|---|
| 让球 spreads | 1.935 | 1.68% | **≥ 2.68%** |
| 大小球 totals | 1.913 | 2.27% | **≥ 3.27%** |

**因此固定的 `MIN_EDGE = 0.020` 是错的**：在实测抽水下它仍处于亏损区，且无法适应不同盘口的赔率差异（1.85 的盘口需要约 5% 的 edge 才打平）。必须逐场按赔率计算。

理由：若模型输出等于市场共识，发布出去就是**承担抽水后的零 EV**，长期必然为负。**"每场都发"这件事本身与"期望为正"矛盾。**

代价是覆盖率下降（多数场次不发），但这正是"只在有信息时才说话"的必然结果。统计页的 `已发布场次` 会显著少于 `已同步场次`，这是设计意图，不是故障。按上述门槛，实际发布率预计仅 **10%~20%**（低于此前按固定 2% 估算的 20%~30%）。

### 4.8 校准与评估

| 指标 | 定义 | 说明 |
|---|---|---|
| `model_brier` | `mean((model_prob − outcome)²)` | 按市场分别统计 |
| `market_brier` | 同上，用去水市场概率 | **必须并列展示**，否则无法判断模型是否优于市场 |
| 可靠性曲线 | 按 `model_prob` 分 10 桶，桶内实际命中率 | 斜率应接近 1 |
| CLV | 发布时赔率 vs 收盘赔率 | 若能取到收盘价，这是最敏感的早期信号 |
| ROI | `Σ profit / Σ stake` | 只统计已发布场次 |

**验收硬标准：`model_brier < market_brier`。** 达不到就说明模型没有产生信息，无论统计页多好看。

### 4.10 为什么不按联赛拆分策略与模型

结论：**第一版不拆，P4 之后用层次模型而不是策略模式，只在"结构差异"出现时才引入多实现。**

#### 4.10.1 关键区分：结构差异 vs 参数差异

| | 结构差异 | 参数差异 |
|---|---|---|
| 定义 | 计算方式不同、输出语义不同 | 同一套计算，系数不同 |
| 例子 | 不同市场的结算规则（让球 vs 大小球）<br>不同数据源的解析协议<br>不同产品类型的字段契约 | 各联赛的进球率、主场优势强度<br>各联赛的赔率效率（抽水比例） |
| 正确表达 | **策略模式 / 多实现** | **同一结构 + 不同参数（层次模型）** |

联赛之间的差异几乎全是**参数差异**。用策略模式表达参数差异，是把统计问题错解成代码问题——代码看起来扩展性好，实际每个分支都在拿一小撮数据独立拟合，方差爆炸。

> 本项目已经有正确的策略模式用例，可以作为对照：`MarketSettlementCalculatorRouter` 按 `MarketTypeEnum` 路由结算器、`AsianOddsProvider` 按数据源切换实现。这两个拆分的理由是**计算规则本身不同**，而不是"配置不同"。

#### 4.10.2 数学原因：样本量不允许

一个赛季的场次（含两个市场，每场最多 2 个预测）：

| 联赛 | 场次/赛季 | ×2 市场 |
|---|---|---|
| 英超 | 380 | 760 |
| 西甲 | 380 | 760 |
| 意甲 | 380 | 760 |
| 德甲 | 306 | 612 |
| 法甲 | 306 | 612 |
| 欧冠 | ~189 | ~378 |
| **合计** | **1,941** | **~3,882** |

叠加 4.7 的选择性发布（动态门槛约 2.7%~3.3%，实测发布率预计仅 10%~20%），**真实可用样本约 400~800 条**。

若按联赛拆成 5~6 个独立模型，每个模型只有 **70~130 条样本**。用这个量级去估"该联赛自己的 λ 基线 + 主场优势 + 阈值"，估出来的参数标准误远大于联赛间真实差异，等于把噪声固化进代码。

参数数量对比：

| 方案 | 参数规模 | 样本/参数 |
|---|---|---|
| 每联赛独立模型（含球队攻防） | 6 × 20 队 × 2 ≈ 240+ | **< 3.3 ❌** |
| 每联赛独立模型（仅联赛基线） | 6 × 3 = 18 | ~22~44 ⚠️ |
| **层次模型（全局 + 联赛偏移收缩）** | 全局 3 + 6 偏移 = 9 | **~44~89 ✅** |

#### 4.10.3 第一版根本没有"训练"这个环节

必须说清楚：**P1~P3 的 `(λh, λa)` 是每场从市场现算的**（见 4.2），不涉及任何拟合，也就不存在"联赛参数"这个东西。

一场英超和一场西甲，反解算法、去水顺序、主盘选择规则完全相同；输入不同自然得出不同的 λ。**此时按联赛分模型没有任何可分的对象。**

只有到 P4 引入历史先验（Dixon-Coles），才第一次出现"需要估计的联赛级参数"——而那时正确的做法是层次模型：

```
λ_home = exp(μ + homeAdv + attack[home] − defence[away] + leagueOffset[league])
λ_away = exp(μ + attack[away] − defence[home] + leagueOffset[league])

leagueOffset ~ Normal(0, σ_league)     ← 部分汇聚：样本少自动收缩向 0
```

`σ_league` 由数据估计。若联赛间确实差异显著，`σ_league` 大，偏移保留；若差异只是噪声，`σ_league` 小，偏移自动收缩到 0。**这个判断由数据做，而不是由开发者拍脑袋写 if-else。**

这也意味着：如果将来发现某联赛确实需要独立参数，层次模型会自动给出——不需要改代码，只需要重新拟合。

#### 4.10.4 什么情况下**才**该引入多实现

只有这三类，且都与"联赛"无关：

1. **赛制结构不同**：涉及加时/点球的赛事（结算规则不同）。当前所有目标市场均为 90 分钟口径，不涉及。若将来做杯赛让球，需单独计算器。
2. **中立场**：欧冠决赛、超级杯等无主场优势。用一个 `neutralVenue` 布尔参数把 `homeAdv` 置 0 即可，**不需要新模型**。
3. **数据源不同**：不同 provider 的字段与协议不同 —— 已由 `AsianOddsProvider` 策略覆盖。

#### 4.10.5 那么现在该做什么

不是"什么都不做"，而是**把联赛做成配置而不是常量**，为将来留出扩展点：

```yaml
app.asian-odds:
  leagues:
    - key: soccer_epl
      display-name: 英超
      enabled: true
      min-bookmakers: 2          # 数据质量门槛，可按联赛收紧
      min-edge: 0.020            # 赔率效率高的联赛可提高阈值
    - key: soccer_uefa_champs_league
      display-name: 欧冠
      enabled: false             # 待 M0 补验 scores 覆盖
      min-bookmakers: 3          # 欧战报价家数更多，门槛可提高
```

这样做的价值：**当数据证明某联赛确实需要不同处理时，改配置即可，不改代码**。而如果过早写成策略模式，等发现"其实差异不显著"时，那些分支会变成必须维护的死代码。

#### 4.10.6 一句话总结

> 联赛差异用**参数**表达，市场与数据源差异用**策略**表达。前者交给收缩估计，后者交给接口。把前者写进 `switch`，等于用代码固化一个尚未被数据验证的假设。

### 4.11 预测、推荐与统计口径

「每场都预测」「加置信度」「后期按置信度算期望」这三件事放在一起，如果概念不分开，会得出**看起来很漂亮但完全不可采信**的结论。这一节定义清楚。

#### 4.11.1 四个概念必须分离

| 概念 | 定义 | 决定什么 |
|---|---|---|
| **预测** | 对一场比赛给出概率与方向 | 分析能力 |
| **推荐** | 从预测中选出"值得下注"的子集 | 策略表现 |
| **置信度** | 模型对这个判断有多确信（市场离散度、残差、样本量） | 估计的**可信程度** |
| **edge** | `model_prob − market_prob` | 是否有**正期望** |

关键：**决定期望的是 edge，不是置信度。** 置信度只影响"这个 edge 估计有多可信"。

四象限：

| | edge 小 | edge 大 |
|---|---|---|
| **置信度高** | 4.7 已过滤，不发布 | **唯一值得推荐的区域** |
| **置信度低** | 不碰 | 可能有价值但估计不稳，需降权 |

很多预测产品失败的根因就是把"我很有信心"当成"我很有价值"——在"市场共识确定、但自己没有优势"的场次上给出高置信度推荐，而那些场次期望恰好等于 `−抽水`。

#### 4.11.2 竞彩与亚盘的定位不同

| | 竞彩（HAD / HHAD） | 亚盘 / 大小球 |
|---|---|---|
| 选项概率 | 三选一，如 0.60 / 0.25 / 0.15 | 二选一，接近 0.50 / 0.50 |
| 抽水占比 | 高（热门项尤甚） | 相对低，但**远高于预期**：全量 bookmaker 中位 4.2%（让球）/ 5.6%（大小球），仅精选低抽水庄可到 1.7%~2.5%（实测见 4.5.1） |
| 适合做什么 | **全量预测 + 全量公开（记录与复盘）** | **选择性推荐（策略）** |
| 是否应对外"推荐" | **否** | 是 |

因此回答「竞彩每场都做预测吗」：**是，但它是"记录"不是"推荐"。**

全量预测、全量公开、包括错的，这正是项目"敢让人查账"的信任资产。而亚盘/大小球才承担"选择性推荐"的角色。两者不应混在同一套 ROI 口径里统计——竞彩的超低命中率会污染亚盘的策略评估。

#### 4.11.3 致命陷阱：事后按置信度筛选

**错误做法**：今天对 100 场都做预测，第二天结果出来后，挑出「置信度高的那 20 场」算 ROI。

这个 ROI 是**虚高**的，而且无法复现。原因：筛选时你已经知道结果，等价于用未来信息挑选样本（post-hoc selection / look-ahead bias）。只要筛得足够细，任何随机噪声都能被筛出一组"高胜率"子集。

**必须区分两种用途**：

| 用途 | 做法 | 结论效力 |
|---|---|---|
| **探索性分析** | 事后按任意维度分桶看表现 | 只能生成**假设**，不能作为策略有效性的证据 |
| **验证性统计** | 阈值在结果产生**之前**固定，前推统计 | 唯一可采信的效力 |

正确流程：

```
第 1~30 天：固定阈值 T1 → 按 T1 发布 → 记录结果
第 31 天：   用前 30 天数据评估 T1，决定是否调整为 T2
第 31~60 天：按 T2 发布 → 记录结果（T1 期间的结论不再参与）
```

这称为滚动前推（walk-forward）。**评估某一天的表现时，只能使用当天之前确定的规则。**

工程上的保障：`predictions` 表里 `edge`、`model_prob`、`market_prob`、`confidence` 全部冻结不可变（V22 字段已纳入 `protect_published_prediction()`），结算后无法回改。这样"事后调参再回算"在数据层面就做不到，避免了自欺。

#### 4.11.4 每天推荐多少：多重比较必须校正

「不可能每天全部推荐」不仅是产品体验问题，更是统计问题。

若一天对 50 场做检验，显著性水平 0.05，即使全部是噪声，也会有约 **2~3 场"显著"**。场次越多，"发现优势"的概率越高——但那是假阳性。

约束设计：

```yaml
app.recommendation:
  max-per-day: 5              # 每日推荐上限，硬约束
  min-edge: 0.020             # 事前固定的 edge 门槛
  min-confidence: MEDIUM      # 事前固定的置信度门槛
  order-by: edge              # 排序键，取 Top-N
```

推荐列表 = 满足 `edge ≥ min-edge 且 confidence ≥ min-confidence` 的场次，按 `edge` 降序取前 `max-per-day` 条。**两个阈值都必须事前固定并记录版本**，否则无法做 4.11.3 的前推统计。

若某天无场次达标，**就空着**。这比"勉强凑几场"有价值得多——空仓也是一种正确决策。

#### 4.11.5 统计口径分层

四个层次，用途不同，**页面上必须分开呈现，不可混算**：

| 层 | 指标 | 样本范围 | 回答的问题 |
|---|---|---|---|
| **L1 模型质量** | `model_brier` vs `market_brier` | **全量预测**（无论是否推荐） | 模型是否比市场更有信息 |
| **L2 策略表现** | ROI、命中率、最大回撤 | **事前规则筛出的推荐子集** | 这套规则是否赚钱 |
| **L3 探索分桶** | 按 `edge` / 置信度 / 联赛分桶的 ROI | 全量预测 | 阈值该如何调整（仅生成假设） |
| **L4 早期信号** | CLV（发布时赔率 vs 收盘赔率） | 推荐子集 | 策略是否有效（**最灵敏**） |

两个硬规则：

1. **L1 必须用全量。** 若只用推荐子集算 Brier，会把"模型算得准但不值得下注"的场次排除掉，得到虚假的模型质量。
2. **L2 只能用事前固定阈值的子集。** 任何事后筛选的结果都归入 L3。

以及一条优先级规则：

3. **最终验收权只归 L2。**「能不能长期赚钱」这个问题只有实测 ROI 能回答，其余三层都是诊断工具：L1 回答「模型有没有信息」，L4 回答「优势方向对不对」（且与 L2 在理论上等价），L3 回答「阈值该往哪调」。任何一层的漂亮数字都不能替代 L2 的实测结论；反过来，L2 短期为正也不构成有效证据（ROI 的统计方差极大，见 4.11.6 的样本效率对比）。

L3 的每个桶必须标注样本量，**样本 < 30 的桶不展示结论**，只显示数据点，避免读者从 5 场样本里读出趋势。

#### 4.11.6 CLV 为什么值得优先做

ROI 需要几百场才能达到统计显著（二项分布方差大），但 **CLV 几十场就能看出方向**：

```
CLV > 0 意味着：你在赔率变差之前买到了，市场随后向你的方向移动
```

如果长期 CLV 为正而 ROI 暂时为负，通常只是运气；若 CLV 为负，即使短期 ROI 为正，也几乎必然会在长期回归为负。**在样本不足的第一阶段，CLV 是唯一能提前判断策略真伪的指标。**

**计算方式**

```
CLV = (发布时赔率 / 收盘赔率) − 1
```

等价概率表述：`收盘隐含概率 − 发布隐含概率`。

例：主队赢盘以 1.95 发布，收盘降至 1.85 →
`CLV = 1.95 / 1.85 − 1 = +5.4%`，即「以 51.3% 的价格买入市场最终认为值 54.1% 的东西」，获得约 **2.8 个百分点的信息优势**。

**为什么方差远小于 ROI**

ROI 混合了「预测准确性」与「比赛随机事件」（红牌、误判、补时进球），后者是不可控噪声；CLV 只比较「你的判断 vs 市场最终判断」，剥离了结果随机性。因此同样的样本量下，CLV 的信噪比高一个量级。

**恒等式：长期 ROI 就是长期平均 CLV**

这不是经验之谈，在「收盘价反映真实概率」的假设下可以直接推出：

```
收盘去水概率        p_close ≈ 真实概率 p_true
单场期望收益        EV      = p_true × 买入赔率 − 1
CLV（用去水收盘概率）= p_close × 买入赔率 − 1
∴ EV ≈ CLV
```

**换句话说：CLV 不是「另一个指标」，而是「期望收益」这个量的另一种算法。** 二者在理论上相等，只在估计效率上不同：

| | 何时可得 | 是否受比赛随机性污染 | 达到显著所需样本 |
|---|---|---|---|
| ROI | 必须等比赛结束 | 是（红牌、误判、补时进球） | 数千场 |
| CLV | **开赛前即可算出** | 否 | 数十~数百场 |

「数千场」不是修辞。粗略估算：赔率 1.95、真实胜率 52%（edge ≈ 1.4%）时单场收益标准差 σ ≈ 0.97；要把 95% 置信区间半宽压到 2 个百分点，需

```
n ≈ (1.96 × 0.97 / 0.02)² ≈ 9,000 场
```

一年 2,000 场需要四到五年。**这就是「等结算结果来验证策略」在实践中不可行的原因**——不是方法错，是效率太低，等于用五年时间买一个迟到的是非判断。

因此：

- **CLV 长期为负 → 长期 ROI 必然为负**，哪怕当前 ROI 还是正的（这是最需要警惕的假象）
- CLV 为正但 ROI 为负 → 通常只是运气，样本增大后收敛
- 实现细节：CLV 必须用**去水后的收盘概率**计算，否则会与抽水混在一起，失去「等于期望收益」这一性质

**但 CLV 有一个前提假设必须诚实地承认**：它依赖「收盘价 ≈ 真实概率」。主流联赛资金充分、赔率效率高，这个假设基本成立；而流动性差的联赛收盘价本身就有偏差，此时 CLV 不可靠。**这也是推荐先做主流联赛的另一个理由。**

**代价：取收盘价需要增加抓取频率**

收盘价 ≈ 开赛前最后一次抓取。这意味着每日 odds 抓取从 1 次增到 2 次（早间生成预测 + 晚间取收盘），配额随之翻倍：

| 配置 | 每日 credits | 每月 |
|---|---|---|
| odds × 1 次 × 5 联赛（`spreads,totals` = 2/联赛） | 10 | 300 |
| **odds × 2 次 × 5 联赛** | **20** | **600** |
| scores 隔日 × 5 联赛（2/联赛） | ~5 | ~150 |
| **合计（含 CLV）** | | **~750** |

**免费档 500 credits 不足以支撑 5 联赛 + CLV。** 三条出路：

1. **CLV 先单联赛试点**（1 联赛 × 2 次 + 赛果 ≈ 270/月），验证有效性后再决定是否付费推广
2. 上 $30 付费档（20,000 credits），完全无压力
3. 只在关键联赛做双抓，其余单抓

推荐第 1 条：**CLV 的价值恰恰在于用最小样本判断策略真伪，单联赛几十场就够给出方向。**

### 4.12 为什么估参数，而不是统计历史命中率

一个常见的误解是：「既然只看长期期望，那统计历史命中率就够了。」

问题在于：**历史平均是一个标量，它回答「过去发生了什么」，不能回答「这场新比赛的 EV 是多少」。**

#### 4.12.1 EV 属于未来，历史统计只是估计量

期望值（EV）是概率分布的属性，是事前概念：

> 「本场 EV = +7.25%」的含义是：**若同样的条件重复无数次，平均每次收益为 +7.25%。**

它描述的是重复实验的长期平均，而不是对已发生结果的总结。我们无法观测的只是**真实 EV**：

| 概念 | 定义 | 可观测 | 用途 |
|---|---|---|---|
| **真实 EV** | 客观存在的期望 | ❌ | 决策的真正依据（不可知） |
| **模型 EV** | 用概率模型事前估计 | ✅ | 发布与筛选的依据 |
| **实测 ROI** | 用结算结果事后估计 | ✅ | 最终验收（方差大） |
| **CLV** | 用市场价格估计 | ✅ | 早期信号（与真实 EV 理论等价） |

后三者都是对第一个的**估计量**，区别只在效率与偏差。**因此「历史统计」是测量工具，不是结论本身。**

**但必须同时说清另一半：模型 EV 不能「自证」，却必须用于决策。**

| 用途 | 是否有效 | 说明 |
|---|---|---|
| **决策**：算出来决定这场发不发、下不下 | ✅ 必须 | 没有它就没有任何行动依据 |
| **验证**：用模型 EV 的预测值证明模型有效 | ❌ 循环论证 | 用假设验证假设 |

「不能自证」与「必须使用」并不矛盾，它对应科学方法里的**假设**：假设必须敢于提出（否则无法行动），检验必须独立（否则是自欺）。

完整闭环：

```
模型 EV（事前假设）→ 发布下注 → 比赛结果 → 实测 ROI（事后检验）→ 修正模型
```

因此「看长期胜率与赔付结构来算期望」这件事本身完全正确——它就是实测 ROI，也是最终验收。需要警惕的只有一种做法：**用模型 EV 的数字去替代实测 ROI 的数字**。

#### 4.12.2 三个阶段的分工（CLV 不参与预测）

预测、决策、评估是三件事，原料不同，容易被混为一谈：

| 阶段 | 时点 | 输入 | 产出 |
|---|---|---|---|
| **预测** | 赛前 | 市场赔率 → 去水 → 主盘 → 反解 λ | **概率** `(p_cover, p_over)` |
| **决策** | 赛前 | 模型概率 vs 市场概率 | `edge` → `模型 EV` → 发不发 |
| **评估** | 赛后 | 实际结算结果 / 收盘赔率 | **实测 ROI**（裁判）、CLV（早期信号）、Brier（诊断） |

注意两点：

1. **预测的产出是概率，不是 EV。** EV 是「概率 × 赔率 − 1」算出来的期望，属于决策阶段。
2. **CLV 在物理上不可能参与预测。** 它的计算依赖收盘赔率，而收盘价在预测发布**之后**才形成。若拿 CLV 去做预测，等于用未来信息预测过去。

CLV 唯一的「反向」用途是**修正模型**：若某类场次的 CLV 系统性为负，说明模型在该类场景存在偏差，应回到预测阶段调整。这是反馈，不是输入。

#### 4.12.3 两种方法的能力边界

用户的真实疑问是「过去的统计凭什么指导新比赛」。这个问题对不同做法有完全不同的答案：

| | 统计历史命中率 | 估计分布参数（本方案） |
|---|---|---|
| 产出 | 一个标量：过去 500 场命中 52% | 一组参数：`λh, λa` |
| 能否计算新比赛 | **不能**——新比赛不在样本内 | **能**——代入任意参数即可 |
| 隐含假设 | 未来与过去同分布 | 弱得多：只需进球生成机制稳定 |
| 新数据到来 | 只能重算平均数 | 可逐场更新参数，影响自动衰减 |

**参数是生成机制，样本只是它的产物。** 估出机制，才能对尚未发生的比赛给出概率；只统计产物，只能对过去做描述。

这解释了 4.2 为什么选择「从当场市场反解 λ」而非统计历史命中率：**今晚这场比赛用的是今晚的盘口，而不是三年前的命中率。** 历史数据只在 P4 引入先验时参与，且权重由样本量自动调节（收缩）。

#### 4.12.4 前提与局限

参数估计并非无条件有效，必须承认两个前提：

1. **结构假设正确**：若进球不服从泊松（例如存在严重的比分相关性、红牌效应），参数估计同样失效。这正是 4.8 要求用 Brier 与校准曲线验证模型设定的原因——**要先证明模型形式可用，再谈参数准不准。**
2. **生成机制相对稳定**：联赛规则、球队强度若发生剧变（升降级大换血、赛制改革），历史对该联赛的约束力下降。应对方式是时间衰减，而非一次性拟合。

## 5. 结算设计

### 5.1 统一 margin 模型

```
让球：margin = (homeScore − awayScore) + handicapLine
大小球：margin = (homeScore + awayScore) − totalLine

margin > 0 → 赢
margin = 0 → 走
margin < 0 → 输
```

验算：阿森纳让 -1.25，1:0 胜 → `margin = 1 − 1.25 = −0.25` → 拆 `−0.5`（输）+ `0`（走）→ **半输**。即"让一球/球半，赢一球输半"，正确。

### 5.2 拆盘与收益

| 小数部分 | 处理 |
|---|---|
| `.5` | 半球盘，无走盘 |
| `.0` | 整数盘，`margin = 0` 走盘 |
| `.25` / `.75` | 拆为 `line − 0.25` 与 `line + 0.25` 两个半盘分别判定 |

合并规则：

| 两个半盘 | 结果 | `stake = 1` 时净收益 |
|---|---|---|
| 赢 + 赢 | `WIN` | `price − 1` |
| 赢 + 走 | `HALF_WIN` | `(price − 1) / 2` |
| 走 + 走 | `PUSH` | `0` |
| 输 + 走 | `HALF_LOSS` | `−0.5` |
| 输 + 输 | `LOSS` | `−1` |

### 5.3 SettlementWriter 分派

```
prediction_type = SPORTTERY → 现有路径（HAD / HHAD），不动
prediction_type = ASIAN     → 新路径（ASIAN_HANDICAP / ASIAN_TOTAL_GOALS）
    两个市场分别独立结算，一个方向为空则不结算该市场
    不要求 handicapPick（三向枚举）非空
```

现有 `SettlementWriter:100` 的 `getHandicapPick() == null` 检查必须改为**仅对 SPORTTERY 生效**，否则 ASIAN 会在第二道闸门再次被拦。

幂等仍由既有机制保证：先按 `(prediction_id, market_type, is_current)` 查已有当前结算，存在即跳过；重跑不产生重复行，`profit` 不变。

## 7. 分阶段实施

| 阶段 | 内容 | 验收 |
|---|---|---|
| **A. 结算闭环** | 市场枚举 + 2 个计算器 + SettlementWriter 分派 | 构造 5 种盘口（半球/整数/四分之一 × 赢输走）矩阵测试全通过；重跑幂等 |
| **B. 聚合与主盘** | 逐家去水、中位数、最平衡线选择 | 用真实响应 fixture 验证三次主盘选择命中 Pinnacle；`count < 2` 正确跳过 |
| **C. λ 反解模型** | 网格搜索 + 概率投影 + 残差过滤 | 给定 `(p_cover, p_over)` 能反解出 λ 并回投出与输入一致的概率（往返误差 < 1e-4） |

| **E. 概率落库与统计** | V22 迁移 + 统计页并列双 Brier | 统计页同时展示 `model_brier` 与 `market_brier` |

## 8. 风险与未决

### 8.1 已知风险

| 风险 | 影响 | 应对 |
|---|---|---|
| 让球盘报价家数少（实测 8/18） | 中位数不稳定 | 门槛设为 2 家，并落库 `bookmaker_count`，统计时可按家数分层 |
| 两市场无解 | 该场无法预测 | 残差阈值过滤，记录跳过原因，计入健康指标 |
| 主盘与真盘仍可能偏离 | 结算口径与实际下注盘口不一致 | 落库实际使用的 line，允许事后审计 |
| 选择性发布导致覆盖率低 | 用户观感"没什么可看" | 前端明确区分"今日可分析"与"今日无优势"，不隐藏 |

### 8.2 必须承认的边界

**第一版模型的概率仍然源自市场。** 它比"押低水方"强，因为做了联合估计与去水，但它不是独立于市场的预测。因此：

- 在与市场对比的 Brier 上，第一版**可能只是略优或持平**
- 真正的信息增益要等 P4（Dixon-Coles 先验）与 P5（赔率漂移）
- 在此之前，统计页必须如实标注"模型概率由市场反解，不构成独立预测"

#### 8.2.1 命中率的现实预期（避免设错目标）

以实测主盘赔率 1.935 为例，`EV = 命中率 × 1.935 − 1`：

| 命中率 | 收益率 | 说明 |
|---|---|---|
| 50.00% | **−3.25%** | 市场共识水平，必亏（这就是抽水） |
| 51.68% | 0.00% | 盈亏平衡点 |
| 52.68% | +1.94% | **发布门槛**（含 1% 安全边际） |
| 54% | +4.49% | 优秀 |
| 55% | +6.43% | 顶尖水平 |
| 57% | +10.30% | 极罕见 |
| 60% | **+16.10%** | 长期基本不存在 |

**关键结论：盈利门槛是 52.7%，不是 50%，更不是 60%。**

60% 命中率对应 16% 的长期收益率——这个量级的绩效在体育投注领域几乎不存在。把目标设在 60% 会导致两种坏结果：要么永远觉得"不够好"而反复调参过拟合，要么用极小样本的漂亮数字自我欺骗。

**合理的现实目标**：长期命中 **53%~55%**、ROI **2%~5%**。全球成熟模型团队的长期水平大致就在这个区间，能做到已经说明模型有真实信息量。

#### 8.2.2 同样的命中率，赔率决定生死

| 命中率 | 赔率 1.85 | 赔率 1.935 | 赔率 2.10 |
|---|---|---|---|
| 52% | −3.8% | +0.6% | +9.2% |
| 54% | **−0.1%** | +4.5% | **+13.4%** |
| 56% | +3.6% | +8.4% | +17.6% |

计算：`EV = p × odds − 1`

这张表解释了**为什么选择亚盘/大小球而非竞彩**：不是命中率更高，而是赔率结构让你在同等命中率下获得更高收益。也解释了为什么「选择性发布」不仅筛概率，还要看赔率——**在 1.85 的盘口上，54% 的命中率仍然亏钱**。

**难度真正的所在**：不是把命中率推到 60%，而是**在 52.7% 这个窄带上稳定地、可验证地站住**。因为市场去水后就是 50%，你需要的 2.7% 优势必须来自真实信息；而模型自身的估计误差如果也在这个量级，edge 就会被噪声淹没。这正是要求 `SAFETY` 边际、要求 CLV 交叉验证、要求样本量的原因。
